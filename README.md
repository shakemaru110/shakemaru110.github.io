# ギャラリー画像ビューア

e-hentai.org のギャラリーURLから、各サムネイルのリンク先にある大きな画像をページ順に縦に表示します。
Pixiv・X向けの処理は、ギャラリー向けに置き換えています。

## 使い方

1. https://e-hentai.org/g/番号/トークン/ のURLを入力し、Enterを押します。
2. 一覧が複数ページに分かれている場合も、最後のページまで画像ページリンクを取得します。
3. スクロールすると、表示位置に近い画像ページから大きな画像URLを取得して表示します。
4. 失敗した画像は「再読み込み」で新しいリンクを取得できます。

ギャラリー内の画像ページへのリンクと、各画像ページの id="img" の画像だけを使います。
広告・プロフィール・おすすめ画像をまとめて収集する処理はありません。
ログインやアクセス制限の解除は行いません。

## 画像の扱い

Workerが取得するのは一覧ページと画像ページのHTMLです。
画像本体は元の配信先からブラウザのimg要素へ直接読み込みます。
Workerで画像を取得・保存・中継しません。ブラウザによる表示通信と通常のキャッシュは発生します。
画像リンクには有効期限があるため固定保存せず、必要なときに取得し直します。
画像ページのリンク取得は同時2件までです。

## API

- GET /api/images?url=ギャラリーURL&page=0
  - 1ページ分の画像ページリンクと一覧の総ページ数を返します。
- GET /api/image?url=画像ページURL
  - そのページの本文画像URLを返します。画像本体は返しません。

取得対象はHTTPSのe-hentai.orgの/g/と/s/形式に限定しています。
表示する画像の配信先は、HTTPSのhath.network配下、ehgt.org、e-hentai.orgに限定しています。

## 確認用URL

https://e-hentai.org/g/4270520/0b04a91d26/

調査時、一覧は10ページあり、最後の画像ページ番号は197でした。
先頭画像ページから本文画像URLを取得でき、外部参照元を指定したHTTP HEADで200応答を確認しました。
画像の表示は取得先・画像配信先の稼働や制限に左右されます。
Cloudflareからのアクセスが拒否される可能性もあり、公開後の実環境確認が必要です。

## 検証

Node.jsがある環境では次を実行します。

    node --test backend/worker.test.mjs

テストは架空のHTMLと画像URLを使い、実画像を取得・保存しません。
実サイトの構造変更時は、一覧リンクと本文img要素の抽出処理の見直しが必要です。
